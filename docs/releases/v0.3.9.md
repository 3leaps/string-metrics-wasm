# string-metrics-wasm v0.3.9 Release Notes

**Release Date**: 2026-06-15 **Status**: Standalone-binary packaging fix, smaller package, and
toolchain/CI modernization

v0.3.9 is a packaging and maintenance release. It fixes a startup crash when the library is bundled
into standalone compiled binaries, substantially shrinks the published npm package, and modernizes
the test toolchain and CI. There are **no public API changes** — all exports keep their existing
synchronous signatures and behavior, and metric results are unchanged.

## Standalone-Binary & Bundler Packaging Fix

Previously the loader read the sibling `.wasm` asset at module top-level via
`readFileSync(new URL(..., import.meta.url))`. Tools that compile an application into a single
standalone binary (for example `bun build --compile`) rewrite that asset path but do not embed the
bytes, so the package crashed with `ENOENT` on startup — even for consumers that never called a
metric, because the top-level `await` made initialization unconditional on import.

This release changes the loader in two ways:

- **Lazy initialization.** The WASM module now initializes **synchronously on first use** instead of
  at import time. Importing the package is side-effect-free; a consumer that never calls a metric
  performs no initialization.
- **Embedded bytes.** The WASM binary is embedded (base64) in the published JavaScript and decoded
  in-process, so there is no runtime filesystem read on any runtime. The package now works inside
  bundlers and standalone compiled binaries with no extra asset-handling configuration.

The public API stays synchronous and unchanged.

## Smaller Published Package

The npm package shrank from **~545 kB to ~180 kB packed** (~520 kB unpacked):

- The generated embedded-WASM constant is typed as `string`, so its declaration file is one line
  instead of a ~300 kB inferred string-literal type (which also slowed consumer typechecking).
- The now-redundant copies of the binary are no longer published: the generated `src/wasm-inline.ts`
  source blob and the raw `pkg/web/*.wasm`. The bytes ship embedded in `dist/wasm-inline.js`; the
  wasm-bindgen JS glue is still included.

The package-contents CI check and the post-publish verifier both assert this contract (embedded
payload + glue present, raw `.wasm` absent).

## Toolchain & CI Modernization

- **Vitest 4**: upgraded the test stack (`vitest`, `@vitest/coverage-v8`) and migrated coverage
  thresholds to the `coverage.thresholds` config shape required by Vitest 2+.
- **Dependencies**: `@types/node` to v24; routine in-range refresh of Biome, Prettier, TypeScript,
  and js-yaml. `wasm-pack` remains pinned to 0.13.x. The unused `@vitest/browser` dev dependency was
  removed, and `biome.json` migrated to the Biome 2.5 schema.
- **CI**: the test matrix now runs on **Node.js 22 and 24** (replacing end-of-life Node 20). GitHub
  Actions were moved off the deprecated Node 20 runtime (`actions/checkout` → v6,
  `actions/setup-node` → v6, `softprops/action-gh-release` → v3), and the third-party
  `jetli/wasm-pack-action` was replaced with a direct `cargo install wasm-pack` step.

## Tests

Added unified-API coverage for every `score()`, `distance()`, and `suggest()` metric (camelCase and
snake_case aliases) plus the unknown-metric error paths. This keeps coverage above the project's 90%
thresholds under Vitest 4's AST-aware measurement, which counts statements and lines more granularly
than Vitest 1 did. The full suite is 176 unit tests plus 127 rapidfuzz-rs fixture cases.

## Compatibility

- No public API change; no metric-result or fixture changes.
- Multi-runtime support (Node.js, Bun, Deno) preserved.
- Drop-in upgrade from v0.3.8.
